# 덕스텝 기획 메모

## 문제

- **대상**: 목표 직무가 있거나 찾는 중인 대학생. 전공과 코딩 경험은 묻지 않는다.
- **문제**: 공고를 읽어도 오늘 뭘 할지 모르고, 해 둔 경험은 흩어져서 취업 때 찾기 어렵다.
- **관찰**: 계획은 학기 초에 끝나고, 경험 정리는 지원서 마감 직전에 몰린다.
- **기대 효과**: 공고만 넣어도 오늘 할 일이 나오고, 끝낸 일이 증거로 쌓여 다음 계획을 바꾼다.

## 가설

공고를 넣자마자 오늘 할 일 3개가 나오면, 사용자는 2주 뒤에도 계속 쓴다.

## 완료 기준

지인 5명 중 3명이 14일 동안 주 3일 이상 대시보드를 연다.
플래너는 어떤 데이터도 밖으로 보내지 않으므로, 설정 화면의 `최근 14일 사용일`을 테스터가 직접 알려 준다.

## MVP

- 공고 붙여넣기, 근거 문장이 붙은 역량 추출, 못 읽은 요건 표시
- 경험 은행 수동 입력과 증거 기반 갭 진단
- 졸업까지 로드맵, 이번 주 계획표, 오늘 할 일 최대 3개
- 시험·과제 준비 시간을 뺀 가용 시간 계산, 직접 추가와 날짜 이동
- 졸업요건 입력
- 브라우저 자동 저장, 내 HTML 저장, JSON 백업과 복원

## 백로그

- LMS·메일·캘린더 자동 수집
- 강의 녹음 전사, 팀플 기여 분석
- 자소서 소재 매칭, 포폴 사이트 생성
- 학교별 졸업요건 YAML, DUCK LIBRARY Notion 연동
- 사전을 넘어서는 AI 공고 분석

## 유저 스토리

| 크기 | 스토리 | 인수 조건 |
| --- | --- | --- |
| M | 학생이 공고를 넣어 요구 역량을 알고 싶다 | 필수·우대를 나누고, 각 역량에 근거 문장을 붙이고, 못 읽은 요건을 숨기지 않는다 |
| M | 학생이 경험을 등록해 부족한 역량을 알고 싶다 | 증거가 없는 경험은 충족으로 세지 않고, 등록 즉시 다시 계산한다 |
| M | 학생이 가능한 시간에 맞는 계획을 받고 싶다 | 하루 3개를 넘기지 않고, 마감 준비 시간을 빼고, 시간이 모자라면 못 다룬 역량을 알려 준다 |
| M | 학생이 자기 데이터로 대시보드를 만들고 싶다 | 설치 없이 생성하고, 저장한 HTML을 다시 열면 그대로 이어지며, 외부 전송이 없다 |

## 스프린트 1 (2주)

목표: 본인 목표 직무로 공고 입력부터 오늘 할 일까지 한 번 끝까지 돌린다.

매일 시작 전 세 줄: 어제 한 일, 오늘 할 일, 막힌 것.
